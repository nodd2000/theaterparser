# Theaterparser — план проекта (v2)

Агрегатор информации о драматических спектаклях России (позже — Беларусь, Казахстан и другие
русскоязычные страны) по образцу nachtkritik.de: база всего текущего репертуара + сводка прессы
по каждой постановке. Первичный источник — Telegram-каналы театров, критиков, блогеров, СМИ.

## 0. Принятые решения

| # | Решение |
|---|---|
| Охват | Весь текущий репертуар, только драма, пока только Россия |
| Сущности | Театры, сцены, спектакли, персоны (режиссёры, художники, актёры, критики) |
| Источники | ~30 TG-каналов на старте (список — `docs/sources.md`), сторонний справочник театров для карты источников |
| Оперативность | Минуты |
| Контент | Цитата + ссылка на рецензию; фото перезаливаем к себе (с кредитом фотографа) |
| Модерация | Каждая сформированная публикация уходит в Telegram-бот, публикуется только после подтверждения |
| Пользователи | Учётные записи и комментарии нужны, но регистрацию пока не открываем (фаза 5); своих рецензий нет, открытый API не нужен |
| LLM | Подписка OpenCode Go (использование в серверном приложении проверено) |
| Хостинг | Всё на серверах в РФ; доступ к Telegram и LLM — через VPN |
| Название | theaterparser (рабочее) |
| Фронтенд | SPA без серверного рендеринга, дизайн по мотивам nachtkritik.de, язык — русский |

## 1. Важные следствия решений

### 1.1 Telegram из РФ
С 10.02.2026 Роскомнадзор официально замедляет Telegram, по ряду регионов доступ фактически
отсутствует. Все сервисы живут на серверах в РФ, а исходящие запросы к Telegram (t.me, Bot API)
и к LLM идут через VPN с выходом за рубежом.

Реализация: контейнер `vpn` с Xray-core (клиент) по вашему ключу. Ключ (ссылка `vless://…`
или готовый `config.json`) хранится только в `.env`/секретах на сервере, в репозиторий не попадает;
при старте контейнера скрипт собирает из ссылки `config.json` с outbound на ваш сервер и
inbound'ами SOCKS5 (`vpn:1080`) и HTTP (`vpn:8118`), доступными только внутри docker-сети.
Через прокси ходят `collector` (t.me/s), `moderation-bot` (Bot API) и LLM-клиент — адрес
задаётся переменными `TG_PROXY_URL`, `LLM_PROXY_URL`. `site-collector`, БД и сайт работают
напрямую (сайты театров в РФ часто не пускают зарубежные IP). Healthcheck контейнера — запрос
к `https://t.me` через прокси. Если VPN
отвалился — сборщик ставит опрос на паузу с экспоненциальной задержкой и пишет алерт в лог,
после восстановления догоняет пропущенное по `last_message_id`.

Параллельно: часть театров уже дублирует каналы в MAX (Александринский, РАМТ) — закладываем
абстракцию источника, чтобы позже добавить MAX и VK без переделки пайплайна.

### 1.2 Как читать Telegram: с аккаунтом или без

**Без аккаунта (выбираем для старта).** У публичного канала есть веб-лента `https://t.me/s/<username>`:
HTML с последними ~20 постами, текстом, ссылками на фото, датами, просмотрами; листается назад
через `?before=<id>`. Ни аккаунта, ни ключей не нужно.
- 30 каналов × опрос раз в 1–2 минуты — нагрузка небольшая, задержка укладывается в «минуты».
- Ограничения: только публичные каналы; канал с включённой защитой контента может не отдавать
  ленту; разметка — не API и иногда меняется (парсер покрываем тестами на сохранённых страницах).

**С аккаунтом (резерв, при росте до сотен каналов или для каналов без веб-ленты).** Как это
выглядит для вас:
1. Отдельная SIM / номер, на него регистрируется обычный Telegram-аккаунт, включается 2FA-пароль.
2. На my.telegram.org получаем `api_id` / `api_hash`.
3. Один раз запускаем команду входа на сервере: Telegram присылает код на этот аккаунт,
   вы вводите код и пароль → создаётся файл сессии, дальше демон работает сам.
4. Аккаунт подписывается на каналы и получает новые посты мгновенно (push, без опроса).
Риски: бан аккаунта при агрессивной выгрузке истории (ограничиваем скорость), с октября 2025
операторы РФ ограничили регистрацию — номер лучше зарегистрировать заранее.

Код сборщика делаем с общим интерфейсом `Collector`, реализации `TgWebCollector` (старт) и
`TelethonCollector` (позже), переключение — настройка канала.

### 1.3 Весь репертуар ≠ Telegram
По Telegram-постам полный репертуар не восстановить: каналы пишут о премьерах и ближайших
показах, а не о спектаклях, идущих 10 лет. Поэтому **парсинг страниц репертуара сайтов театров
переносим в MVP** для театров из стартового списка: страница «Репертуар/Спектакли» → LLM
извлекает список спектаклей (название, автор, режиссёр, сцена, возраст, продолжительность,
дата премьеры) → загрузка в каталог через ту же модерацию. Telegram даёт новые премьеры,
рецензии и фото, сайт — базовый каталог.

### 1.4 LLM: OpenCode Go
- $10/мес, лимиты в долларах: $12 за 5 часов, $30 в неделю, $60 в месяц; OpenAI-совместимый
  API (`https://opencode.ai/zen/go/v1`), модели — открытые (DeepSeek, GLM, Kimi, Qwen, MiniMax…).
- Оценка расхода: 30 каналов ≈ 150 постов/день; классификация дешёвой моделью + извлечение
  для ~50 релевантных ≈ 15 млн токенов/мес — порядка единиц долларов. Разовая загрузка
  репертуара (~30 театров) и истории каналов — растягиваем на несколько дней из-за лимита на 5 часов.
- Риски: серверы в США/ЕС/Сингапуре — вызовы через VPN-прокси; список моделей меняется.
  Поэтому клиент LLM — через OpenAI-совместимый
  интерфейс с настраиваемыми `base_url`/моделью, замена провайдера (YandexGPT, GigaChat,
  OpenRouter) — без изменений кода.

### 1.5 Учётные записи пользователей в РФ (фаза 5, пока не делаем)
Пока регистрации нет — сайт не обрабатывает персональные данные посетителей, оператор ПДн
не нужен. Когда откроем регистрацию: по 149-ФЗ (в ред. 406-ФЗ, с 01.12.2023) сайт обязан авторизовывать пользователей из РФ через
российский номер телефона, Госуслуги, ЕБС или российскую систему идентификации. Вход только по
email не подходит. План: **Яндекс ID + VK ID** (OAuth), позже — вход по SMS. Плюс: уведомление
РКН об обработке персональных данных, политика конфиденциальности, модерация комментариев
(кнопка «пожаловаться» → тот же бот).

### 1.6 SPA без SSR
Каталог спектаклей живёт за счёт поискового трафика; SPA индексируется Яндексом хуже.
Принимаем как решение; страницы делаем с уникальными URL, `sitemap.xml` и мета-тегами,
чтобы при необходимости позже включить пререндер публичных страниц без переписывания.
Стек: React + Vite + TypeScript + TanStack Query/Router (Next.js без SSR не даёт преимуществ).

## 2. Архитектура

```
 Сервер в РФ (Docker Compose)
 ┌───────────────────────────────────────────────────────────────┐
 │  collector (t.me/s) ──┐        site-collector (сайты театров) │
 │        │ через VPN    ▼                 │ напрямую            │
 │        │      очередь (Redis + arq) ◄───┘                     │
 │        │              ▼                                       │
 │        │      processor ── LLM (OpenCode Go, через VPN)       │
 │        │              ▼                                       │
 │        │      черновики ──► moderation-bot ──(VPN)──► вы       │
 │        │              ▼ ✅                                     │
 │        └──► PostgreSQL + S3 (фото) ◄── api (FastAPI)          │
 │                                           ▲                   │
 │  vpn (Xray, SOCKS5/HTTP-прокси)         │                   │
 │                                    web (SPA React) + nginx    │
 └───────────────────────────────────────────────────────────────┘
```

### Стек
Python 3.12, `uv`, монорепо. FastAPI + Pydantic v2; SQLAlchemy 2 (async) + Alembic;
PostgreSQL 16 (`pg_trgm`, полнотекстовый поиск с русской морфологией); Redis + arq;
httpx + selectolax (парсинг t.me/s и сайтов); aiogram 3 (бот); S3-совместимое хранилище
(MinIO или Yandex Object Storage / Selectel); Docker Compose; ruff, mypy, pytest.

### Сервисы
| Сервис | Назначение |
|---|---|
| `collector` | Опрос t.me/s каждые 1–2 мин, выгрузка истории, сохранение сырых постов, повторная проверка правок |
| `site-collector` | Раз в сутки — страницы репертуара театров |
| `processor` | Классификация, извлечение, сопоставление с каталогом, сборка черновика |
| `moderation-bot` | Отправка черновиков, приём решений, правки |
| `api` | Публичный API для сайта (позже — auth, комментарии) |
| `web` | SPA |
| `vpn` | Исходящий туннель для Telegram и LLM |

## 3. Пайплайн обработки поста

1. **Сохранение** сырого поста (неизменяемо): канал, id, дата, текст, ссылки, фото, альбом,
   репост из какого канала, хэш. Правка поста = новая версия.
2. **Классификация** (дешёвая модель): `premiere_announce` / `premiere_report` / `review` /
   `photos` / `cast_change` / `repertoire_news` / `irrelevant`. Нерелевантное дальше не идёт.
3. **Извлечение** (JSON-схема): театр, название спектакля, автор/первоисточник, постановщики,
   актёры, даты, город, для рецензий — автор и ключевая цитата (1–3 предложения).
4. **Сопоставление**: канал театра → его спектакли в приоритете; нечёткий поиск по названию
   и алиасам (`pg_trgm`), совпадение режиссёра; кандидаты с оценками уверенности.
5. **Черновик** в бот:
   ```
   🎭 РЕЦЕНЗИЯ · МХТ им. Чехова · «Вишнёвый сад» (реж. И. Иванов)
   Автор: Павел Руднев (@teatrovidenie) · 18.10.2026
   «…цитата…»
   Совпадение: спектакль #412 (0.93) | другие: #398 (0.41)
   [✅ Опубликовать] [✏️ Изменить] [🔀 Другой спектакль] [🆕 Новый спектакль] [❌ Отклонить]
   ```
   Похожие черновики (один анонс в пяти каналах) склеиваются в одну карточку.
6. **Публикация** в каталог после ✅. Решения модератора сохраняются — это обучающая выборка
   для улучшения промптов и оценки качества.

## 4. Модель данных

- **Country**, **City**.
- **Theatre**: название, алиасы, тип, город, адрес, сайт, URL страницы репертуара, внешние id
  (Wikidata, Культура.РФ). **Stage** — сцены.
- **Person**: ФИО, алиасы, фото, внешние id. **Production** ↔ **Person** через **Credit**
  (роль: режиссёр, художник, композитор, хореограф, актёр + персонаж).
- **Production**: название, алиасы, театр, сцена, автор/первоисточник, дата премьеры, статус
  (анонсирован / в репертуаре / снят), возраст, продолжительность, описание.
- **Source**: канал или сайт, тип (театр / критик / блогер / СМИ / институция), связь с Theatre
  или Person, способ сбора, последний прочитанный id.
- **RawPost**, **Extraction** (версия промпта/модели, JSON, уверенность),
  **Draft** (статус модерации, решение, кто и когда).
- **Review**: Production, автор (Person), Source, URL, дата, цитата.
- **Photo**: файл в S3, фотограф, Production, исходный пост.
- **User** (провайдер OAuth, внешний id), **Comment** (Production/Review, статус),
  **Subscription** (на театр/персону/город — фаза 2).

## 5. Сайт (по мотивам nachtkritik.de)

- Главная: лента последних премьер и рецензий, блок «Пресса за неделю».
- Каталог: город → театр → спектакль; фильтры по городу, театру, режиссёру, статусу, дате премьеры.
- Календарь премьер.
- Карточка спектакля: шапка с данными постановки, команда и состав, фотогалерея,
  «Пресса о спектакле» (цитаты со ссылками, по дате), комментарии.
- Страницы театра, персоны, критика/источника.
- Поиск. RSS по городу/театру.
- Страна в навигации есть сразу (пока одна).
